# Английский в Telegram

В меню «🇬🇧 Английский» выбери «Добавить в словарь» или «Повторение». Слова,
выражения и фразы добавляются одинаково. Выйти можно в любой момент.

Готовую пару можно отправить в любом порядке. Например, `put up with — терпеть` или
`Я уже в пути — I'm on my way.`. Подойдут также две строки одного сообщения или
два сообщения подряд. Бот сразу покажет карточку, которую можно сохранить. Каждая
сторона может содержать до 600 символов. Если пришла одна сторона, бот предложит
добавить перевод или нажать «Подготовить с ИИ». К готовой паре можно запросить
пример или пояснение с ИИ, сохранив обе стороны карточки.

Для подготовки с ИИ бот выбирает направление перевода по первой букве ввода.
Английское выражение можно прислать с контекстом, чтобы модель выбрала одно
значение. К русскому тексту можно добавить английскую попытку с новой строки
после «Мой вариант:». Русская сторона карточки сохраняет исходную формулировку
пользователя. «Исправление:» заменяет исходный ввод, обычное уточнение добавляет контекст.
В ответе — одна формулировка, один полезный оборот и короткий пример.
«Уточнить с ИИ», «Пример с ИИ» и «Пояснение с ИИ» меняют только черновик. Запись в Notes
происходит исключительно по «Сохранить», после чего можно сразу прислать новый
ввод. Предложения модели следует просмотреть перед сохранением.

Поддерживаются текст, голос и уточнения. Для голосового ввода
одной стороны бот автоматически готовит вариант после транскрибации. Распознанный текст
виден при открытии учебного результата. Уточнение дополняет контекст; сообщение
`Исправление: исправленный текст` полностью заменяет ошибочную расшифровку.
Назначение, дата и исходный черновик голосового задания фиксируются при приёме,
поэтому переход в дневник или перезапуск ничего не перенаправляет. Результат
открывается собственной кнопкой, не перезаписывает активный черновик сам собой и
не попадает в дневник. При недоступной модели готовая расшифровка остаётся доступна
с кнопкой повторной подготовки. Слишком длинный текст можно просмотреть по
страницам и прислать нужный фрагмент. Лимит одного учебного ввода — 1000 символов; сама русская мысль для одной карточки — до 600.

## Канонический текст и словари

Основной словарь хранится в `Tags/English/words.md`. Новые карточки из Telegram
и мобильного приложения сохраняются сюда. Тематические словари читаются из
`Tags/English/Dictionaries/*.md`. Для каждого словаря укажи короткое постоянное
имя файла строчными латинскими буквами, цифрами и дефисами, например
`blood-diamond.md`. Заголовок первого уровня `# Кровавый алмаз` задаёт видимое имя.
Имена `all` и `general` зарезервированы для «Все слова» и «Основной».

«Все слова» включает карточки из всех файлов. «Основной» и тематические
словари включают карточки из своих файлов. Можно выбрать несколько словарей
и повторять их как один набор. В Telegram выбор открывается по кнопке
«Повторение», в Android — над карточкой и списком слов.

Строка карточки начинается с английского текста в обратных кавычках, затем
идёт дефис и русский перевод.
Словарь можно править вручную. Следующий вход в повторение обнаружит изменения.

```markdown
[[10-Oct-2026]]
- `yield` - уступать дорогу
  Контекст: дорожный знак
  Пример: Yield to pedestrians.
- `put up with` - терпеть
- `I spent half an hour trying to fix it.` - Я потратил полчаса, пытаясь это исправить
  Пояснение: spend time doing something; spent — прошедшая форма
  Пример: I spent an hour reading.
```

Поддерживаются маркеры списка `-` и `*`, даты `[[DD-Mmm-YYYY]]` и записи без дат.
Подполя `Пояснение:`, `Пример:` и `Контекст:` с отступом в два пробела необязательны.
Новые записи бота помещаются в секцию текущей **логической даты
Notes** (TIMEZONE_OFFSET_HOURS и DAY_START_HOUR), со ссылкой на дневную заметку.
Дата выбранной для дневника старой заметки на это не влияет. При голосовом
уточнении сохраняется дата исходного учебного черновика.

Сервис присваивает карточке стабильный ID в скрытом HTML-комментарии. Сохраняй
комментарий при ручной правке перевода или перемещении карточки между словарями,
чтобы сохранить историю. Старым записям без ID миграция добавляет комментарий
с прежним ID. Новая ручная запись получает его при первой оценке. При подсказке
и пропуске Markdown не изменяется.

Для переноса существующих карточек из `words.md` используй
`make move-english-dictionary < manifest.json` после обновления Core и English.
В JSON укажи `id` словаря, `title` и массив `card_ids` из скрытых маркеров.
Команда копирует карточки с прежними ID и датами, сверяет результат и затем
убирает исходные записи. При прерывании ту же команду можно запустить ещё раз.
Если некоторое время есть две одинаковые записи, «Все слова» показывает одну
карточку, а источником считается тематический словарь.

## Бесконечное повторение

Открой «Повторение» и выбери один или несколько словарей. Бот показывает
одну сторону и предлагает подсказку, ответ, пропуск или скрытие. После оценки
или пропуска он сразу показывает следующую
карточку. «В меню» завершает показ. При повторном входе сервис возвращает
текущую карточку, даже после перезапуска Telegram или перехода в другой клиент.

Каждый набор выбранных словарей и «Все слова» имеют свой круг и позицию в
PostgreSQL. Выбор двух фильмов создаёт один перемешанный круг, куда входят
доступные карточки обоих фильмов. Порядок выбора словарей на набор не влияет.
Telegram и Android продолжают с одной позиции, когда открыт один и тот же набор.
Оценки, число ошибок, серия «Легко» и оставшиеся пропуски хранятся по ID
карточки и направлению перевода. Они общие для всех наборов. Например, оценка
в словаре одного фильма учитывается и в следующем круге двух фильмов. Новый
круг расходует пропуск только у карточек из своего пула. Повторное открытие
того же круга сохраняет его порядок, стороны и позицию.
Клиенты без параметра словаря используют «Все слова».

«Скрыть карточку» исключает её из повторения во всех наборах, включая
«Все слова». Текст в Obsidian, оценки и интервалы сохраняются. Карточку можно
вернуть из меню «Скрытые карточки» в Telegram или из списка скрытых в словаре
Android. Текущий круг сохраняет исходные позиции для скачанных карточек.
Новые круги формируются из доступных карточек.

В каждом круге доступные карточки встречаются по одному разу. Если у карточки
пора показать хотя бы одно направление, она попадает в очередь. Порядок зависит
от сохранённого случайного значения, номера круга и ID карточек. Время и порядок
строк в заметке на него не влияют. При исчерпании очереди сервис автоматически
начинает новый круг. Если все карточки выбранного набора временно пропущены,
сервис сразу учитывает пустые круги этого набора и открывает ближайший непустой.

| Действие | Следующее появление | Серия «Легко» |
| --- | --- | --- |
| Не вспомнил | Следующий круг | Сброс |
| С трудом | Следующий круг или через круг с равной вероятностью | Сброс |
| Легко | После пропуска 2–3, 4–5, 7–9 или 14–16 кругов | На одну ступень выше, максимум 4 |
| Пропустить | Следующий круг | Сохраняется |

Сервис выбирает пропуск по сохранённому случайному значению, ID карточки,
номеру круга и оценке. Интервал и оценка сохраняются вместе. При переходе с
расписаний отдельных наборов берётся наибольший остаток пропусков, совместимый
с последней оценкой и ступенью. Уже начатые очереди, токены и история сохраняются.
Сохранённые ступени 4 и 5 обе дают 14–16 пропущенных кругов при следующей оценке
«Легко».

Правки Markdown подхватываются при запросе текущей карточки или оценке. Новые
записи участвуют со следующего круга. Удалённые карточки больше не показываются,
их история сохраняется. Если другой клиент уже оценил карточку или её текст
изменился, бот обновляет экран.

## Сервис и хранение

### Дашборд занятий

Дашборд [English · занятия](https://grafana.mralexandrov.duckdns.org/d/notes-english)
показывает сохранённые ответы, уникальные карточки, дни занятий и подходы за
выбранный период. Дни считаются по Москве. Если между двумя оценками прошло больше
30 минут, начинается новый подход. Подход целиком попадает в период по времени
первого ответа. Пропуски показаны в дневном графике отдельно от ответов.

Дашборд использует имеющуюся историю PostgreSQL. Время события — время, когда
сервер принял ответ. Ответы, отправленные Android после работы офлайн, могут
появиться одной пачкой. История содержит ID карточки и оценку, поэтому по ней
можно считать повторения, но нельзя вывести слова, словари или клиент.

Дашборд собирается из `monitoring/templates/notes-english.json` и SQL командой
`make monitoring-dashboard`. `monitoring/observability.json` доставляет его
в `notes-bot/notes-english.json` на центральную Grafana. Для источника данных
используется `monitoring/notes-english.datasource.tpl.yaml`. После миграции
примените `ops/english/grafana-reader.sql` в БД `english`, задайте этой роли
отдельный пароль и подставьте его при установке файла datasource на WSL.
Роль читает только два представления. Порт 15435 слушает адрес Russia в
tailnet. HAProxy принимает подключения от узла Grafana `100.64.0.10`
и от хоста WSL `100.64.0.3`.

Когда контейнер Grafana теряет доступ к tailnet, источник данных может
использовать Unix-сокет в уже смонтированной папке provisioning. На WSL
установите `ops/english/notes-english-grafana@.socket` и одноимённый `.service`
в `/etc/systemd/system`, затем выполните `sudo systemctl daemon-reload` и
`sudo systemctl enable --now notes-english-grafana@maxim.socket`, где `maxim` —
владелец каталога `.monitoring`. Укажите в приватном YAML источника данных
`url: /etc/grafana/provisioning/datasources/notes-english` и перезагрузите
provisioning источников данных. Сокет доступен группе Grafana, исходящее
соединение идёт через Tailscale на WSL, пароль PostgreSQL остаётся обязательным.
Чтобы вернуть прямое подключение, восстановите URL из шаблона, перезагрузите
provisioning и отключите экземпляр `.socket`.

### API

Контейнер `english` обслуживает `english.v1.EnglishService`. Словари доступны
через `ListDictionaries`. Идентификаторы комбинированного набора передаются
в `dictionary_id` через `+`. `GetReview` возвращает текущую карточку набора,
`AdvanceReview` получает её токен и оценку либо пропуск. Повтор запроса с тем же
токеном и действием безопасен и возвращает актуальную позицию. `SaveCard` и
`ListCards` сохраняют формат материала. Старый `GradeCard` оставлен в proto для
совместимости схемы. Клиенты повторения переходят на `GetReview` и `AdvanceReview`.
`SetCardHidden` принимает стабильный ID карточки, желаемую видимость и ID
операции. Повтор той же операции возвращает актуальную видимость.

Словарь читается из vault через внутренние `ReadMarkdown` и `ReplaceMarkdown`
Core. Сохранение использует ожидаемую ревизию и маркер операции, чтобы параллельная
правка через Core и повтор запроса не затирали данные и не создавали дубли.
Obsidian и файловая синхронизация используют свои механизмы разрешения конфликтов.
Для повторения нужен доступ к Core, чтобы показывать актуальный Markdown.

У слова два расписания, EN → RU и RU → EN. Оценка меняет интервал и ступень
только у показанного направления. Сервис выбирает сторону с более ранним
сроком, при равенстве — псевдослучайно. Сторона фиксируется при сборке круга,
поэтому оценка из другой очереди не меняет токены уже скачанных карточек.
Старые общие оценки остаются в истории. Оба направления получают прежний срок
первого повтора и начинают накапливать собственные оценки с первого ответа.

Контейнер `postgres-english` хранит только ID карточек, оценки, ступени, круг и
курсор. Оценка и переход к следующей карточке фиксируются одной транзакцией.
Telegram хранит свой экран и черновики в Redis. Источник состояния повторения —
PostgreSQL.

### Запуск, перенос и резервные копии

Обычная доставка запускает миграцию до обновления Telegram. Локально её выполняет
`make up` или явно `make migrate-english`. Сервис при запуске проверяет версию схемы.

Миграция объединяет прежние слова и фразы в `words.md`, сохраняет ID и маркеры
сохранений, однократно импортирует историю оценок и число забываний из
`.notes-bot/english-progress.json`. Старое расписание по времени сменяется
первым кругом с нулевой ступенью. Для уже начатого старого прохода Telegram
открывает новую очередь. Исходный журнал и `phrases.md` остаются в vault.
При переносе или восстановлении берите vault и дамп английской БД из одного
согласованного снимка. При откате на выпуск до разделения сервисов новые
оценки останутся в PostgreSQL и будут доступны после возврата на новую версию.

По умолчанию сервисы работают во внутренней Docker-сети. Укажите отдельный
`ENGLISH_DB_PASSWORD` при первичной инициализации базы. Существующая конфигурация
может использовать `DB_PASSWORD` как начальный пароль. Чтобы запустить сервис
отдельно, передайте `CORE_GRPC_HOST`, `CORE_GRPC_PORT` и `ENGLISH_DATABASE_URL`
для PostgreSQL. Для миграции задайте `ENGLISH_LEGACY_JOURNAL` с путём к файлу
на доступном для чтения снимке vault и выполните `english migrate`. Telegram
подключается по `ENGLISH_GRPC_HOST` и `ENGLISH_GRPC_PORT`. Оба gRPC API рассчитаны
на доверенную приватную сеть. Для внешнего клиента потребуется защищённый вход
с аутентификацией.

Подготовку выполняет `english.v1.TutorService` на существующем поисковом
worker через тот же защищённый gRPC-маршрут. Этот обработчик не имеет зависимости
от индекса, БД или vault. Он использует уже настроенные LLM_HOST/LLM_PORT и
AGENT_MODEL (SEARCH_AGENT_MODEL в Compose), FEATURE_LLM_GENERATION. Прямой
устаревший адрес Ollama в Telegram для этого раздела не используется. Одновременно
разрешены два учебных запроса, каждый ограничен пятью минутами; недоступность или
Unimplemented при последовательном обновлении оставляют черновик для повтора.
Загрузка модели в память может занимать несколько минут. В чате показывается статус
подготовки, в это время можно прислать готовую пару. Предел совпадает с существующим
лимитом вызовов поискового worker.
Подготовка текстового варианта, повтор, пример и пояснение выполняются в фоне:
остальные кнопки и сообщения доступны во время ожидания. Новый ввод отменяет
предыдущий запрос. Результат или ошибка обновляют только тот же актуальный
черновик; после выхода в другой раздел они не меняют текущий экран. При остановке
frontend запрос отменяется, после перезапуска подготовку можно повторить из
сохранённого черновика. Голосовые задания по-прежнему используют постоянную очередь.
Штатный CI сначала активирует новый digest поискового worker на WSL и лишь затем
обновляет приложение на Russia. После доставки нужно проверить сам новый RPC на
реальном маршруте: успешного обновления одного frontend недостаточно.

Модель получает только выбранный ввод, уточнение и текущий preview. Дневник и
поиск по личному vault в этих сценариях не используются. Inference — существующий
Ollama на WSL/Mac; Russia не загружает модели и не включает локальный fallback.

## Проверки

`make check` включает Go/race, интеграционные сценарии и проверки protobuf.
`make test-english-db` проверяет миграцию, продолжение круга и параллельные
оценки на отдельном PostgreSQL, заданном через `TEST_ENGLISH_DATABASE_URL`.
