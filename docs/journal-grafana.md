# Notes · Дневник в Grafana

Дашборд с UID `notes-journal` читает производные данные из отдельной базы
`journal` в существующем экземпляре PostgreSQL сервиса `postgres-english`.
Core обновляет данные при старте и каждые 15 минут. Снимок заменяется в одной
транзакции, при ошибке остаётся последняя целая версия. В vault записей нет.

## Как считаются показатели

- **Оценка дня.** Поле `Оценка` из YAML дневной заметки, дата из имени файла
  `Daily/DD-Mmm-YYYY.md`. Линия соединяет выставленные оценки. Значения 0–4
  окрашены красным, 5–7 оранжевым, 8–10 зелёным. При отсутствии оценки точки нет.
- **Символы по дням.** На графике показан объём текста дневных заметок.
  Среднее и максимум в легенде пересчитываются за выбранный период.
  Пустая дневная заметка учитывается с нулём.
- **Календарь.** Переключатель над дашбордом выбирает текст, связи или зал.
  В режиме «Год» цвет точки меняется от красного к зелёному с ростом объёма.
  В режиме «Месяц» видно значение. Текст — Unicode-символы в теле дневника
  без frontmatter, строк задач,
  комментариев, кода и вложений. В тексте учитывается подпись ссылки, если она есть.
  Связи — уникальные существующие Markdown-заметки со ссылкой на дневную заметку
  или из неё, включая ссылки в свойствах YAML. Поддерживаются Obsidian wiki-ссылки
  и внутренние Markdown-ссылки. Самоссылки, неоднозначные короткие имена и ссылки
  на отсутствующие файлы пропускаются. Скрытые папки, Trash и Templates исключены.
- **Зал.** Один маркер за день, если есть выполненный чекбокс `Зал`
  (`[x]` или `[X]`, без учёта регистра названия). День берётся из имени
  дневной заметки, в которой стоит чекбокс.
- **Зависимости.** На диаграммах X — символы или связанные заметки, Y — оценка.
  Рядом показаны коэффициенты Пирсона и размер выборки за выбранный период.
- **Люди.** Ребро появляется при явных ссылках на две карточки из `Tags/People/`
  в одной дневной заметке. Вес ребра — число таких дней. Узел показывает число
  дней, в которые в дневнике вместе упоминались этот и хотя бы один другой человек.

Все даты на дашборде отображаются по Москве. SQL для панелей лежит в
`monitoring/sql/notes-journal`. Сборка и проверка JSON — `make monitoring-dashboard`
и `make monitoring-check`. На Grafana нужен Business Calendar (проверено на
`marcusolsson-calendar-panel` 4.2.3). Остальные панели встроены в Grafana.

## Первое включение

1. После доставки кода выполните `ops/journal/provision.sql` в базе `postgres`
   от администратора PostgreSQL контейнера `postgres-english`. Передайте psql
   через его окружение два разных случайных пароля `JOURNAL_WRITER_PASSWORD`
   и `JOURNAL_READER_PASSWORD`. Скрипт создаёт базы и роли при первом запуске
   и сохраняет пароли существующих ролей при повторе. Пароли хранятся вне Git.
2. На хосте Notes запустите `make migrate-journal` для создания отчётной схемы и
   выдачи прав чтения. В приватном `.env` задайте `JOURNAL_DB_DSN` с хостом
   `postgres-english`, базой `journal` и пользователем `journal_writer`.
   Активируйте Core штатным digest-деплоем. Пустой DSN отключает обновление отчёта.
3. В Grafana установите datasource из `monitoring/notes-journal.datasource.tpl.yaml`
   с паролем `journal_grafana` и перечитайте provisioning. Шаблон использует
   существующий приватный endpoint PostgreSQL `:15435` через tailnet. Для хоста
   без маршрута из контейнера Grafana подходит тот же Unix-сокет, который
   форвардит English PostgreSQL.
4. Доставьте JSON по схеме `monitoring/observability.json` в каталог
   `notes-bot/` центральной Grafana. Убедитесь, что анонимный доступ выключен
   и что доступ к datasource имеют только люди, которым разрешено видеть оценки
   и имена. Grafana получает счётчики и названия карточек людей без текста заметок.

Для отключения уберите `JOURNAL_DB_DSN` и активируйте Core. Снимок можно
повторно собрать из vault при следующем запуске.
